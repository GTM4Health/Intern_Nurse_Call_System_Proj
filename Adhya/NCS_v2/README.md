# N-Bed Nurse Call System

## 1. Overview

The N-Bed Nurse Call System is an ESP32-based system designed to allow patients to request nurse assistance and allow nurses to acknowledge and resolve those requests.

The system supports multiple ESP32 devices, with each device assigned to a specific ward and bed.

Communication between the ESP32 devices and the central server is implemented using TCP/IP.

---

## 2. System Architecture

```text
Patient / Bed
     |
     | Touch Input
     v
   ESP32
     |
     | TCP/IP
     v
Python TCP Server
     |
     +-------------------+
     |                   |
     v                   v
Web Dashboard       Event Logging
                         |
                  +------+------+
                  |             |
                  v             v
              events.json   events.xlsx
````

---

## 3. Main Components

### ESP32

The ESP32 is installed at the patient bed and is responsible for:

* Detecting patient CALL input
* Detecting nurse ACK input
* Detecting request CANCEL input
* Maintaining the current request state
* Sending events to the Python server
* Identifying itself using its MAC address
* Connecting to the hospital/local Wi-Fi network

### Python Server

The Python server is responsible for:

* Accepting TCP connections from ESP32 devices
* Authorizing ESP32 devices using their MAC addresses
* Receiving events from ESP32 devices
* Maintaining the state of each ward/bed
* Providing the web dashboard
* Managing ESP32 registration
* Recording system events
* Generating Excel event logs

---

## 4. Communication

The system uses TCP/IP for communication between the ESP32 and the Python server.

The ESP32 sends JSON messages to the server.

Example:

```json
{
    "mac": "20:E7:C8:69:08:E0",
    "ward": 101,
    "bed": 2,
    "event": "CALL",
    "time": "16:06:34",
    "call": "16:06:34",
    "ack": "--:--:--"
}
```

Each message is separated using a newline so that the TCP server can process individual events.

---

## 5. ESP32 Authorization

Each ESP32 is identified using its MAC address.

Before an ESP32 can send patient events, its MAC address must be registered through the configuration page.

```text
ESP32
   |
   | REGISTER
   v
Python Server
   |
   +-- MAC registered --> AUTHORIZED
   |
   +-- MAC not registered --> REJECTED
```

Unregistered ESP32 devices are rejected and their events are not added to the event logs.

---

## 6. Event States

The nurse call system uses four states:

```text
IDLE
CALL
ACK
DONE
```

### IDLE

No active patient request.

### CALL

The patient has requested nurse assistance.

Dashboard status:

```text
PATIENT ASSISTANCE REQUESTED
```

### ACK

The nurse has acknowledged the request.

Dashboard status:

```text
NURSE RESPONDING
```

### DONE

The request has been resolved.

Dashboard status:

```text
REQUEST RESOLVED
```

After the request is resolved, the system returns to IDLE.

---

## 7. Event Flow

```text
IDLE
  |
  | Patient CALL
  v
CALL
  |
  | Nurse ACK
  v
ACK
  |
  | CANCEL / RESOLVE
  v
DONE
  |
  | Automatic reset
  v
IDLE
```

## 8. Web Dashboard

The Python server provides a web dashboard for monitoring registered beds.

The dashboard displays:

* Ward number
* Bed number
* Patient call time
* Nurse acknowledgement time
* ESP32 MAC address
* ESP32 online/offline status
* Current request status

Dashboard:

```text
http://localhost:5001
```

---

## 9. ESP32 Configuration

ESP32 devices can be registered through:

```text
http://localhost:5001/config
```

The configuration page allows the administrator to:

* Register an ESP32
* Assign a ward
* Assign a bed
* View registered devices
* Delete an individual device
* Delete all registered devices

---

## 10. Event Logs

The event logging page is available at:

```text
http://localhost:5001/admin
```

The system records events including:

* ESP32 Connected
* Patient Call
* Nurse ACK
* Request Resolved
* ESP32 Disconnected
* ESP32 Registered
* ESP32 Deleted

The logs are stored in:

```text
events.json
events.xlsx
```

The Excel file can be downloaded from the Event Logs page.

## 13. Setup

### Step 1 — Python Server

Install dependencies:

```bash
pip install -r requirements.txt
```

Run the server:

```bash
python tcp.py
```

### Step 2 — Configure ESP32

Open the ESP32 code in Arduino IDE.

Configure:

* Wi-Fi SSID
* Wi-Fi password
* Python server IP
* Ward number
* Bed number

Upload the code to the ESP32.

### Step 3 — Register ESP32

Open:

```text
http://localhost:5001/config
```

Enter the ESP32 MAC address, ward number and bed number.

### Step 4 — Test

After authorization:

1. Touch CALL
2. Verify the dashboard shows the patient request
3. Touch ACK
4. Verify the dashboard shows nurse response
5. Touch CANCEL
6. Verify the request is resolved
7. Check `/admin` for the recorded events

## 15. Security Notes

Wi-Fi credentials and other sensitive information should not be committed to the repository.

Before uploading the ESP32 code to GitHub, replace actual credentials with placeholders:

```cpp
const char* ssid = "YOUR_WIFI_SSID";
const char* password = "YOUR_WIFI_PASSWORD";
```

Runtime device and event files should also generally not be committed to the repository.
